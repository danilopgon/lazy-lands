# Spec: generated-session-ui

**Change**: per-section-regeneration
**Capability**: `generated-session-ui` (new)

---

## Overview

`generated-session-view.tsx` MUST render the 7 canonical sections (see `session-generation`)
and wire the "Regenerate" control per section, replacing the current disabled "Coming
later" button. Authoritative visual source: `handoff/app/views-prepare.jsx`
`GeneratedSession` and `handoff/app/data.js` (lines 197-208) for ids/labels/order.
`route-map.md`'s pointer to `views-sessions.jsx` is stale and MUST be ignored. Per
PRODUCT.md P1, regenerated content is presented as an editable Scribe proposal, never as
a final decision.

---

## Functional requirements

### UI-001: 7-id allowlist and order

`section-label.ts` and `schemas.ts` MUST allowlist exactly the 7 ids from
`session-generation` SG-001 (`synopsis`, `goal`, `opening`, `beats`, `encounters`,
`factions`, `arcs`), and the view MUST render them in that fixed order regardless of
persisted array order.

#### Scenario: All 7 sections render after reload

- GIVEN a session with generated content containing all 7 sections
- WHEN the DM opens the generated-session view
- THEN all 7 sections render in the canonical order, each numbered `/01`..`/07`
  (zero-padded), with its localized label heading

### UI-002: Per-section header — number, label, origin badge

Each section header MUST show its zero-padded number, localized label, and an
`OriginBadge` reflecting `origin`: `✦ Scribe` when `origin === "scribe"`, `✎ Edited by
you` when `origin === "edited"`.

#### Scenario: Origin badge reflects state

- GIVEN a section with `origin: "edited"`
- WHEN it renders
- THEN the badge shows `✎ Edited by you`; an unedited `origin: "scribe"` section shows
  `✦ Scribe`

### UI-003: Tools row — Edit and Regenerate

Each section MUST show an `Edit` control (existing) and a `Regenerate` control
(`ll-linklike muted` styling) when not in editing state. Both controls MUST be hidden
while that section is in editing state.

#### Scenario: Tools hidden during edit

- GIVEN a section is in editing state (inline textarea open)
- WHEN the view renders
- THEN neither `Edit` nor `Regenerate` is visible for that section

### UI-004: Regenerating state (loading)

MUST track regeneration state per section id, independently of other sections. While a
section is regenerating: its `Regenerate` button MUST be disabled and its label MUST
read `Regenerating…` (toggled from `Regenerate`); its body MUST be replaced by a quill
loading affordance (`✒` glyph + "The Scribe is rewriting" with an ellipsis animation).
Other sections MUST remain fully interactive (their own Edit/Regenerate/Save/Cancel
controls unaffected).

#### Scenario: Regenerating one section does not block others

- GIVEN section `encounters` is regenerating
- WHEN the DM clicks `Edit` on section `factions`
- THEN `factions` enters editing state normally while `encounters` still shows the
  loading affordance

#### Scenario: Regenerate button disabled while in flight

- GIVEN section `beats` is regenerating
- WHEN the DM looks at that section's tools row
- THEN the `Regenerate` control is disabled and reads `Regenerating…`

### UI-005: Success state

On a successful regeneration response, the section's body MUST update to the new text,
its `origin` MUST show as `✦ Scribe`, and a toast MUST display "Section regenerated by
the Scribe".

#### Scenario: Successful regeneration updates body and shows toast

- GIVEN section `opening` is regenerating
- WHEN the backend returns the updated `SessionDetailResponse`
- THEN `opening`'s body reflects the new text, its badge shows `✦ Scribe`, and a toast
  reading "Section regenerated by the Scribe" appears

### UI-006: Error state (not in handoff — MUST be specified)

If the regenerate call fails (network error, validation failure, or non-2xx response),
the section MUST keep its previous body and `origin` unchanged, exit the regenerating
state (button re-enabled, label back to `Regenerate`), and a localized error MUST be
surfaced via `ErrorNotice`/toast. This state is not depicted in the handoff prototype and
is a required addition to the visual contract.

#### Scenario: Failed regeneration preserves prior content

- GIVEN section `arcs` has `origin: "edited"` and is regenerating
- WHEN the backend call fails
- THEN `arcs` still shows its original body and `origin: "edited"` badge, the
  `Regenerate` control is re-enabled, and a localized error notice/toast appears

### UI-007: i18n coverage

All new copy MUST be present in both `messages/en.json` and `messages/es.json`,
including: the 7 section label keys, `Regenerate`/`Regenerating…`, the loading phrase
("The Scribe is rewriting…"), the success toast, and the error message.

#### Scenario: Locale switch renders localized regenerate copy

- GIVEN the app locale is `es`
- WHEN a section is regenerating or completes/fails regeneration
- THEN all displayed copy (button label, loading phrase, toast, error) is sourced from
  `messages/es.json`, not hardcoded English strings

## Non-functional requirements

### NFR-UI-1: Motion per DESIGN.md

The quill loading affordance and toast entrance MUST use the existing `ll-quill`/
`ll-ellip` motion primitives and button-press physics already defined in DESIGN.md —
this spec does not introduce new animation primitives.

### NFR-UI-2: Independent per-section state

Regeneration in-flight state MUST be tracked per section id (e.g. a set/map keyed by
`section_id`), not a single global "is regenerating" flag, so concurrent interaction with
non-regenerating sections is never blocked.

---

## Acceptance criteria

1. The view renders exactly the 7 canonical sections, numbered and labeled per
   `handoff/app/data.js`, in fixed order. (UI-001)
2. Each section header shows the correct `OriginBadge` state. (UI-002)
3. Edit/Regenerate are hidden during that section's editing state. (UI-003)
4. Regeneration state, loading affordance, and button disable/label-toggle are tracked
   per section; other sections stay interactive. (UI-004, NFR-UI-2)
5. Success updates body + origin badge + shows the success toast. (UI-005)
6. Failure preserves prior body/origin, exits loading state, and surfaces a localized
   error. (UI-006)
7. All new copy exists in `en.json` and `es.json`. (UI-007)
