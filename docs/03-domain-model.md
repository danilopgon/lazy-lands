# Domain Model

This document defines the main domain concepts of Lazy Lands.

## Core entities

### User

Represents an authenticated Supabase user.

The application does not manage passwords directly. Authentication is delegated to Supabase Auth.

Main fields:

- `id`
- `email`
- `created_at`

### Campaign

Represents a long-running tabletop RPG campaign.

Main fields:

- `id`
- `user_id`
- `title`
- `description`
- `world_state`
- `accumulated_summary`
- `summarized_up_to_session`
- `created_at`
- `updated_at`

Rules:

- A campaign belongs to one user.
- A campaign has many NPCs.
- A campaign has many factions.
- A campaign has many sessions.
- A campaign has many arcs.
- A campaign has many memory facts.

### NPC

Represents a non-player character.

Main fields:

- `id`
- `campaign_id`
- `name`
- `description`
- `current_state`
- `motivation`
- `content_source`
- `created_at`
- `updated_at`

Rules:

- NPCs are scoped to a campaign.
- NPCs can be generated by AI or manually edited by the DM.
- Edited NPC fields should be considered authoritative.

### Faction

Represents a relevant organization or group in the campaign.

Main fields:

- `id`
- `campaign_id`
- `name`
- `description`
- `current_stance`
- `goals`
- `content_source`
- `created_at`
- `updated_at`

Rules:

- Factions are scoped to a campaign.
- Faction reactions should be considered during next-session generation.

### Arc

Represents an open narrative thread, conflict, promise or unresolved situation.

Main fields:

- `id`
- `campaign_id`
- `title`
- `description`
- `status`
- `priority`
- `created_at`
- `updated_at`

Possible status values:

- `open`
- `resolved`
- `dropped`

Rules:

- Only open arcs are included in generation context.
- Resolved and dropped arcs remain stored but are excluded from active context.

### Session

Represents a played or generated campaign session.

Main fields:

- `id`
- `campaign_id`
- `session_number`
- `summary`
- `consequences`
- `generated_content`
- `trace_json`
- `created_at`
- `updated_at`

Rules:

- Sessions are ordered by `session_number`.
- A played session can update the accumulated summary.
- A generated session may contain trace metadata about the generation process.

### MemorySuggestion

Temporary AI-generated candidate memory.

This is not canon.

Main fields:

- `content`
- `type`
- `importance`
- `reason`
- `source_session_id`

Rules:

- Memory suggestions are not persisted as active memory unless accepted by the DM.
- The DM can accept, reject or edit them.

### MemoryFact

A memory accepted by the DM as active campaign context.

Main fields:

- `id`
- `campaign_id`
- `source_session_id`
- `content`
- `type`
- `importance`
- `status`
- `created_at`
- `updated_at`

Possible status values:

- `active`
- `archived`

Rules:

- Only active MemoryFacts are included in generation context.
- MemoryFacts are part of campaign continuity.
- MemoryFacts should be human-approved.

### GeneratedSessionOutput

Structured AI output for a next-session proposal.

Main fields:

- `title`
- `synopsis`
- `main_objective`
- `twist`
- `encounters`
- `faction_reactions`
- `arc_progression`
- `continuity_links`

Rules:

- The backend must validate this output before showing or persisting it.
- Invalid output must be rejected.
- The DM must treat generated content as a draft.

## Value objects

### ContentSource

Represents where a field came from.

Possible values:

- `llm`
- `edited`
- `manual`

Rules:

- AI-generated content can be edited by the DM.
- Edited content is more authoritative than generated content.

### Importance

Used for memories and arcs.

Possible values:

- `low`
- `medium`
- `high`

## Domain invariants

- A user must not access another user's campaign data.
- AI output must not be trusted until validated.
- AI suggestions do not become canon automatically.
- The DM is the authority over campaign memory.
- Generation context must include only data belonging to the active campaign.
